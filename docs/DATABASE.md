# データベースの選び方（初学者向け）

> **方針:** データベースを使う。localStorage のみにはしない。

---

## 初学者向けおすすめ

| サービス | DBの種類 | 難易度 | 備考 |
|----------|----------|--------|------|
| **Supabase** ⭐ | PostgreSQL | ★★☆ | SQL が学べる |
| Firebase | Firestore（NoSQL） | ★★☆ | クラウドDBでデータ永続化 |

**おすすめ: Supabase**

- 無料枠あり
- サーバーを自分で立てなくてよい
- SQL（PostgreSQL）が学習・実務で通じやすい
- HTML/JS から直接 API で読み書きできる

※ 最終決定はユーザーが選ぶ。Firebase 希望でも OK。

---

## ざっくり構成

```
ブラウザ（HTML / CSS / JS）
        ↓ API
   Supabase（PostgreSQL）
        ↓
   データがクラウドに保存される
```

- データは **ユーザーのブラウザだけ** ではなく **DB に保存**
- 別の端末・ブラウザからも同じデータにアクセス可能（設計次第）

---

## アプリでやる CRUD

| 操作 | 英語 | 例（ToDo） |
|------|------|------------|
| 作る | Create | タスクを追加 |
| 読む | Read | 一覧を表示 |
| 更新 | Update | 完了に変更 |
| 削除 | Delete | タスクを削除 |

**CRUD を DB で実装する** のがこのアプリの学習ポイント。

---

## テーブル設計の例（ToDo の場合）

| カラム名 | 型 | 意味 |
|----------|-----|------|
| id | uuid | 一意のID（自動） |
| title | text | タスク名 |
| done | boolean | 完了したか |
| created_at | timestamp | 作成日時 |

※ アプリが決まったら、一緒にテーブル設計する。

---

## セキュリティ（最初はシンプルでOK）

- 最初: **自分だけ使う** 想定で1ユーザー
- Supabase の Row Level Security（RLS）は後からでも可
- まずは「CRUD が動く」ことを優先

---

## 公開

- フロント: Netlify / Vercel（今まで通り）
- DB: Supabase クラウド（別途アカウント作成）

---

## 学習の流れ（予定）

1. Supabase アカウント作成
2. テーブル作成（GUI で OK）
3. JS から insert / select / update / delete
4. アプリの UI とつなぐ

詳細タスクは **アプリ確定後** に `TASK.md` に書く。

---

## やらないこと（今は）

- 自分で MySQL サーバーを借りて構築（時間がかかる）
- Docker / 複雑なバックエンド（1ヶ月・初学者には重い）

Python + SQLite も可能だが、**ネット公開がやや複雑**。  
フロント公開 + Supabase の方が初学者には現実的。
